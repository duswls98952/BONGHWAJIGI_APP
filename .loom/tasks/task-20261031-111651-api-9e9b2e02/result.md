# 작업 결과

- 모바일 화면 API 매칭 리스트를 최신 홈·긴급 대응·프로필·기본 수칙 기획에 맞췄다. 홈의 `나의 사전준비`에 전용 API·응답 필드가 없고 현재 프로필 계약에는 정기 복용약 정보가 없음을 명시했다.
- 주변 재난의 진행 중·종료 모두 3개월 이내 최신순 최대 3건이라는 기획 목표와 현재 OpenAPI의 차이, 2D 경로와 기존 `route_3d`의 차이, 기본 수칙 회피 영역의 데이터 공백을 기록했다.
- 끊어진 `delivery/` 문서 링크를 현재 저장소의 API 문서·사본으로 교체하고, 서버 인계 문서에 계약 결정 항목을 추가했다. OpenAPI, 생성 타입, 앱 코드는 변경하지 않았다.

## 검증

- `npm run check` 통과: TypeScript 검사, 테스트 14개, 문서 12개 링크 검사.
- 최신 기획 문구·사전준비 공백 표기 확인과 `git diff --check` 통과.

## 남은 위험과 다음 행동

- 사전준비 추천, 3개월·3건 필터, 2D 경로 capability, 기본 수칙 회피 분류는 실제 서버 계약이 아직 없다. 서버팀과 API 버전·입력/출처·유효성·오류 상태를 합의한 뒤 OpenAPI와 앱을 연동해야 한다.
