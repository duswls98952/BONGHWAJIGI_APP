# 구현·검증 기록

## 2026-11-01 Android 0.2.1 지도 연결

- TypeScript·45개 테스트(기존40개+좌표/만료/카메라5개)·16개 문서 링크 검사, 웹 번들, Android release 빌드를 통과했다.
- 기존 서명으로 Samsung Android15에 업데이트 설치했다. 실제 네이버 전국 지도·지명·저작권 표기와 시연 위치 저장 후 홈의 위치 마커·좌표·카메라 이동을 CUA 화면으로 확인했다.
- 사용자가 공식 경보 상세에서 붉은 관련 영역과 위치 마커가 함께 보이는 것을 확인했다. 같은 단말의 서버 위치 revision2·유효기간과 사건 bounds·정책 반영을 읽기 대조했다.
- 실제 GPS를 요청하거나 119 연락을 실행하지 않았다. 웹·Expo Go는 명시된 도식이며 실제 웹 지도 검증이 아니다. 키 오류·비행기 모드·iOS·Firebase 원격 푸시는 이번 검증에 포함하지 않았다.
- APK·해시·구현 경계·화면 증거는 [지도 배포 문서](11-naver-map-integration.md)에 기록했다.

## 2026-11-01 현재0.2 앱 구현

- Node24.22.2에서 `npm run check` 통과: TypeScript, 기존14개+신규26개=40개 회귀, 문서 링크 검사.
- `npm run export:android` (Hermes1466모듈), `npm run export:web` (1015모듈) 성공. 네이티브 APK와 실제 단말 검증은 별도 기록한다.
- 개발 서버에서 신규 온보딩 저장→홈→공식원문→경고·대피·위급 단계/문장→기본수칙·119초안 표시를 직접 확인. 전화·문자 전송은 실행하지 않았다.
- [위급 화면](validation/web-critical.png)은 합성 응답을 표시하는 웹 검증 증거다.
- 세션 회전 단일 실행·로그아웃 경쟁·origin분리, 오래된 응답/만료/입력버전 대기, 3단계 정합성, 합성fixture, HTTP/푸시 계약 회귀를 추가했다.
- 일반 서버는 단말 시계 오차 보정까지 포함해 104개 테스트와 HTTPS 합성 흐름 검증을 통과했다. Samsung Android15에서 서명 APK 설치·온보딩·세션 복원·공식 원문과 1·2·3단계 갱신을 확인했고 서버 저장 기록과 대조했다. 무음 해제 후 TTS 청취도 사용자가 확인했다. APK 해시와 단말 검증 범위는 [Android 배포 문서](10-android-delivery.md)에 기록했다.
- 이 초기 0.2.0 검증 시 지도 Client ID와 Firebase가 준비 전이었다. 이후 지도는 위 0.2.1 기록으로 갱신했다. Firebase와 실제 예측 연결은 제외다. 현재 기본 위치는 사용자 선택 일회 공유이고, 백그라운드위치 옵션은 기본 비활성이다.

## 2026-10-31 개발 서버 재확인

- 현재 레포의 `expo`가 51.0.39이고 다른 주요 패키지가 SDK 58 계열이라 Metro가 `ERR_PACKAGE_PATH_NOT_EXPORTED`로 시작하지 못했다. `expo`를 58.0.21로 맞추고 잠금 파일을 갱신했다.
- Node 24.20.0에서 `EXPO_OFFLINE=1 npm run web -- --host localhost --port 8081`로 웹 개발 서버를 시작했다. `http://localhost:8081/`의 HTTP 200과 HTML 응답을 확인했다.
- TypeScript 검사와 핵심 테스트 14개는 통과했다. `EXPO_NO_TELEMETRY=1 npm run export:web`으로 웹 번들을 생성했다.
- `npm run check`의 문서 링크 단계는 `docs/HeoNey/`로 복사된 문서의 기존 상대 경로가 현재 레포에서 연결되지 않아 실패했다. 해당 링크 수정은 이번 서버 실행 범위 밖이다.
- 웹 번들과 HTTP 응답을 검증했다. 실제 기기 실행, 네이버 지도, 푸시, GPS, TTS, 백그라운드 동작은 이번에 검사하지 않았다.

## 2026-10-31 PNG 기반 HTML 시안

- `public/prototype/`에 다섯 PNG를 기준으로 한 독립 정적 HTML 시안을 추가했다. 이 경로의 홍수·프로필·위치·행동 문구는 시각 예시이며 Expo 앱의 실제 데이터 기본값이나 검증된 재난 지침이 아니다.
- 개발 서버에서 HTML, CSS, JavaScript, SVG 네 파일이 모두 HTTP 200으로 제공됨을 확인했다. HTML의 다섯 화면 ID와 내부 이동 링크를 검사했고 JavaScript 문법 및 SVG XML 파싱이 통과했다. 웹 export도 성공해 네 파일이 `dist/prototype/`에 포함됐다.
- 브라우저 자동 시각 검사는 사용 가능한 브라우저 호스트가 없어 수행하지 못했다. 모바일 실기기 표시와 PNG 픽셀 비교는 아직 확인 전이다.

### 후속 화면 점검

- Safari에서 다섯 해시 화면을 열어 홈·긴급 대응·3D 임시·프로필·홍수 기본 수칙의 실제 배치를 확인했다. 긴급 화면의 `기본 수칙`과 `대피로` 이동, 각 화면의 뒤로가기, 프로필 선택 버튼 변경과 아래 항목 스크롤을 확인했다.
- PNG와 다르게 보이던 상태바의 통신 아이콘을 SVG로 조정했다. 프로필 선택 버튼에 `aria-pressed` 상태를 연결했다.
- 이 점검은 데스크톱 Safari에서 폭 390px로 제한한 시안의 확인이다. 실제 모바일 기기 렌더링과 PNG의 픽셀 단위 비교는 아직 수행하지 않았다.

## 실제 단말·서버 검증 전

로그인/토큰 갱신·로그아웃, 실제 API 배포 주소, 지도 계정/Client ID, FCM/APNs 자격 증명, 네이티브 빌드는 준비 전입니다. Expo Go 직접 기기 실행·실제 네이버 지도·알림 수신·GPS·TTS·잠금/절전/앱 종료 후 복구는 이번 자동 검사에 포함하지 않았습니다. 실제 서버에서 단계가 갱신된다는 운영 검증도 아직 없습니다.

푸시 토큰 회전, 알림 영수증 실제 전송, 권한 철회·로그아웃 정리, 위치 전송 재시도/세션 종료, 종료된 앱의 대화 복원, 실제 119 초안·문자/전화 UX는 후속 작업입니다. 이 항목들은 버튼이나 API 함수가 존재한다는 이유로 완료 처리하지 않습니다.

`input_versions` 대기 기준은 현재 실행 메모리에 보관됩니다. 새 로그인 사용자의 캐시/기준 초기화와 앱 종료 후 복원은 인증 구현 시 함께 처리합니다. 백그라운드 위치는 기본 비활성이며 운영 전 새 위치 버전과 응답 재평가의 연계도 실제 서버에서 검사합니다.

## 의존성 점검

`npm audit`에서 13개 항목(높음 3, 보통 8, 낮음 2)이 보고됐습니다. 실제 취약 라이브러리는 Expo 개발/빌드 의존성의 zod 3, glob/minimatch, deepmerge이며 상위 패키지로 전파된 집계를 포함합니다. 앱이 직접 쓰는 zod는 4.6.7입니다.

자동 수정안 일부가 Expo 58 → 51로 내려가므로 `npm audit fix --force`는 적용하지 않았습니다. 개발 도구 문제도 미해결 항목으로 유지합니다. 팀은 Expo의 호환 수정 릴리스를 확인하고 업데이트 후 doctor·타입·번들·기기 검사를 다시 수행해야 합니다. 외부 입력을 빌드 설정에 그대로 넣지 않습니다.
